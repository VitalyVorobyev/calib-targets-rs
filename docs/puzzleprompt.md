I want to run a numerical experiment on the PuzzleBoard construction based on ((3,3)_2) de Bruijn rings.

## Goal

Reproduce the published PuzzleBoard construction and then explore the space of valid de Bruijn-ring pairs to find and rank boards with the best localization properties under unknown (0^\circ,90^\circ,180^\circ,270^\circ) rotation.

Choose Python, Rust, or a combination based on the existing codebase and what makes experimentation easiest. Reuse existing Calibration Targets / PuzzleBoard code where appropriate.

## Mathematical setup

A ((3,3)_2) de Bruijn ring is generated by an Eulerian cycle in the corresponding ring graph. The graph should have:

* 24 vertices
* 168 edges

The original ring is (3\times168). Remove one column to obtain a (3\times167) pattern. Since

[
\gcd(3,167)=1,
]

combining two orthogonal rings produces a periodic PuzzleBoard of size

[
501\times501.
]

Each board cell carries the two binary components coming from the horizontal and vertical rings, giving the four PuzzleBoard marker states.

## Phase 1 — Reproduce and validate

Implement or reuse:

1. Construction of the ((3,3)_2) ring graph.
2. Generation of valid de Bruijn rings from Eulerian cycles.
3. Construction of a (501\times501) PuzzleBoard from a pair of rings.
4. Extraction of local (k\times k) observations.
5. Canonicalization of an observation modulo the four rotations.

Validate basic invariants:

* every generated ring satisfies the de Bruijn-ring property;
* the board period is (501\times501);
* without rotation ambiguity, every (3\times3) observation uniquely identifies its position;
* reproduce, as closely as possible, the published result of roughly 99.33% unique localization for the rotation-aware (3\times3) representation and 100% uniqueness for (4\times4).

If the exact published rings are already present in the repository, test them first.

## Phase 2 — Define board quality

For every candidate pair of rings compute at least:

* fraction of positions uniquely identifiable from a (3\times3) observation modulo rotation;
* number and sizes of collision classes;
* fraction uniquely identifiable from (4\times4);
* minimum Hamming distance between distinct rotation-canonical local codes;
* distribution of nearest-neighbour Hamming distances.

Treat Hamming-distance robustness as an important secondary objective, not only exact uniqueness.

## Phase 3 — Explore the solution space

Do **not** attempt exhaustive enumeration: the number of valid Eulerian cycles is astronomically large.

Instead:

1. Generate diverse random valid Eulerian cycles.
2. Sample many independent ring pairs and establish the distribution of board quality.
3. Implement local mutations that preserve the Eulerian-cycle/de-Bruijn property.
4. Run hill climbing, simulated annealing, evolutionary search, or another suitable discrete optimizer.
5. Maintain a ranked/Pareto set of the best solutions.

Primary optimization objective:

[
\max U_3
]

where (U_3) is rotation-aware (3\times3) localization uniqueness.

Secondary objectives:

[
\max d_{\min},\qquad
\min \text{collision severity}.
]

A particularly interesting question is whether

[
U_3 = 100%
]

is achievable at all.

## Deliverables

Produce:

* a reproducible command/program for running the experiment;
* tests for the mathematical invariants;
* baseline results for the published/reference board;
* statistics from random sampling;
* a ranked list of the best discovered ring pairs and their metrics;
* serialization of the best rings/boards so they can be reused;
* a short README describing the representation, search method, metrics, and results.

Keep the implementation experiment-oriented first. Optimize performance only where profiling shows that candidate evaluation or search throughput is the bottleneck.
