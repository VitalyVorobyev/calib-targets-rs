# Migration Guide — 0.11.0

This guide collects every breaking change in the 0.11.0 release for
upstream consumers of the `calib-targets` workspace, with before/after
snippets for Rust, the JSON config wire format, the Python bindings, the
C ABI, and the WASM / TypeScript surface.

0.11.0 is dominated by one upstream event — **`chess-corners` 1.0**, an API
freeze that removed or reshaped most of the corner front-end's public
surface — plus a batch of workspace-side consolidations that had been
queued behind it.

The changes fall into nine themes:

1. [`chess-corners` 1.0: the ChESS threshold is a plain `f32`](#1-the-chess-threshold-is-a-plain-f32)
2. [`nms_radius` / `min_cluster_size` moved to a `detection` block](#2-nms_radius--min_cluster_size-moved-to-a-detection-block)
3. [`DescriptorRing` is removed](#3-descriptorring-is-removed)
4. [`contrast` / `fit_rms` are gone — and so is the fit-RMS pre-filter](#4-contrast--fit_rms-are-gone--and-so-is-the-fit-rms-pre-filter)
5. [`chess_corners::low_level` moved to the `chess-corners-core` crate](#5-chess_cornerslow_level-moved-to-chess-corners-core)
6. [`nalgebra` 0.34 → 0.35](#6-nalgebra-034--035)
7. [`GridCoords` is replaced by `Coord { u, v }`](#7-gridcoords-is-replaced-by-coord--u-v-)
8. [The seed-and-grow grid builder is retired](#8-the-seed-and-grow-grid-builder-is-retired)
9. [Smaller surface removals](#9-smaller-surface-removals)

Plus the binding-specific summaries:

- [C ABI: `calib-targets-ffi` → 3.0.0](#c-abi-calib-targets-ffi--300)
- [Python](#python)
- [WASM / TypeScript](#wasm--typescript)

If you only read corners off a detection result and never construct config
structs by literal, themes 1–6 do not affect you at runtime — but theme 7
changes the JSON key names of every grid label, so report parsers do need a
look.

**Detection behaviour.** The ChESS response kernel is unchanged between
`chess-corners` 0.11.2 and 1.0.0, so themes 1–3, 5, and 6 are pure API
reshaping with byte-identical output. Theme 4 is the one deliberate
behavioural change in this release, and it is discussed on its own terms
below.

---

## 1. The ChESS threshold is a plain `f32`

`chess_corners::Threshold` — the tagged enum with `Absolute` and `Relative`
variants — is removed. The ChESS strategy now reads a single `f32` as an
absolute floor on the raw response.

**There is no ChESS relative mode any more.** Relative thresholding survives
only on the Radon strategy, where it means "a fraction of the per-frame
maximum". If you were passing `Threshold::Relative(_)` to a ChESS config,
there is no mechanical translation; pick an absolute floor instead. The
workspace default, `15.0`, is a reasonable starting point for 8-bit imagery
and is what `calib_targets::detect::default_chess_config()` uses.

### Rust

```rust
// before
let cfg = DetectorConfig::chess().with_threshold(Threshold::Absolute(15.0));
let low = DetectorConfig::chess().with_threshold(Threshold::Relative(0.05));

// after
let cfg = DetectorConfig::chess().with_threshold(15.0);
let low = DetectorConfig::chess().with_threshold(8.0); // pick an absolute floor
```

### JSON config wire format

```jsonc
// before
{ "threshold": { "absolute": 15.0 } }

// after
{ "threshold": 15.0 }
```

### If you drive `ChessParams` directly

The low-level `ChessParams` had a `threshold_rel` / `threshold_abs` pair.
These collapse into one `threshold` field.

> **Note — your `threshold_rel` was probably already a no-op.** Pre-1.0,
> `chess-corners-core` resolved the floor as
> `threshold_abs.unwrap_or(threshold_rel * max_response)`, and
> `ChessParams::default()` set `threshold_abs: Some(0.0)`. So code that
> defaulted a `ChessParams` and then set only `threshold_rel` was running at
> an absolute floor of `0.0`, not at the relative value it appeared to
> request. Mapping such code to `threshold = 0.0` is exactly
> behaviour-preserving; "preserving" the relative number would be a silent
> behaviour *change*. Two call sites inside this workspace were in precisely
> that state.

### Upstream default moved

`chess-corners` 1.0 changed its own `DetectorConfig::chess()` default from
`0.0` to `30.0`. The workspace has always overridden it and continues to use
`15.0`, so `default_chess_config()` produces exactly the corner set it did
under 0.11. If you build a bare `DetectorConfig::chess()` yourself, you are
now starting from `30.0`.

## 2. `nms_radius` / `min_cluster_size` moved to a `detection` block

Both fields left the ChESS strategy config and became strategy-independent
detection parameters.

### Rust

```rust
// before
let cfg = DetectorConfig::chess().with_chess(|c| {
    c.nms_radius = 3;
    c.min_cluster_size = 2;
});

// after
let cfg = DetectorConfig::chess().with_detection(|d| {
    d.nms_radius = 3;
    d.min_cluster_size = 2;
});
```

### JSON config wire format

```jsonc
// before
{
  "strategy": { "chess": { "nms_radius": 2, "min_cluster_size": 2, "ring": "canonical" } }
}

// after
{
  "strategy": { "chess": { "ring": "canonical" } },
  "detection": { "nms_radius": 2, "min_cluster_size": 2 }
}
```

The Python bindings reject the old key locations with an explicit error
rather than silently defaulting — see [Python](#python).

The *low-level* `ChessParams` keeps both fields; only the facade
`ChessConfig` lost them.

---

## 3. `DescriptorRing` is removed

The descriptor ring radius is no longer independently selectable — the
descriptor always follows the detector's ring radius, which is what the
previous default (`DescriptorRing::FollowDetector`) already did. Delete the
setting; at the default there is no behaviour change.

```rust
// before
let cfg = DetectorConfig::chess().with_chess(|c| {
    c.descriptor_ring = DescriptorRing::FollowDetector;
});

// after
let cfg = DetectorConfig::chess();
```

The `descriptor_ring` JSON key and the C `descriptor_use_radius10` field are
removed likewise.

---

## 4. `contrast` / `fit_rms` are gone — and so is the fit-RMS pre-filter

`chess-corners` 1.0 no longer reports `contrast` (local light/dark
separation) or `fit_rms` (corner-model fit residual) on a corner. A corner
now carries a sub-pixel position, two undirected axes each with a 1σ angular
uncertainty, and a `strength` response magnitude.

Consequently:

- **`calib_targets_chessboard::ChessCorner` loses `contrast` and `fit_rms`.**
  Construct it with `position`, `axes`, `strength`.
- **`AdvancedTuning::max_fit_rms_ratio` is removed** (it was the ratio `k` in
  `fit_rms ≤ k · contrast`, default `0.5`). Delete it from Rust literals,
  JSON configs, Python `ChessboardParams`, and the C
  `ct_chessboard_advanced_t` struct.
- **`CornerDescriptor::axes` is now `Option<[AxisEstimate; 2]>`.** The
  workspace always fits orientation, so `None` maps to the existing
  no-information sentinel (`AxisEstimate::default()`, `sigma = π`).

### The replacement admission gate

The chessboard pipeline's Stage 1 pre-filter used to admit a corner's axes
when `strength ≥ min_corner_strength` **and**
`fit_rms ≤ max_fit_rms_ratio · contrast`. The second half is no longer
expressible. It is replaced by a gate on the axes' own reported uncertainty:

```text
strength ≥ min_corner_strength   AND   max(σ₀, σ₁) ≤ axis_align_tol_rad
```

`axis_align_tol_rad` (default 15°) is the tolerance the topological builder's
cell test *already* applies to those same axes. The gate is therefore
**derived, not a new constant**: an axis estimate whose own 1σ spread is
wider than the alignment window cannot answer the question the cell test
poses of it, so admitting it adds noise to edge classification rather than
evidence. Loosening the cell test loosens admission by exactly the same
amount, and there is no separate knob to tune — which is why nothing replaced
`max_fit_rms_ratio` in `AdvancedTuning`.

> The topological builder also carries a `max_axis_sigma_rad` (0.6 rad). That
> is a much looser internal backstop, not an admission gate, and it is
> unrelated to this change.

**Behavioural note.** This is the one place in 0.11.0 where detection output
moves. Across the workspace regression corpus the change is recall-positive
in aggregate, and — the property that actually matters — **no frame gained a
wrong `(i, j)` label**; the wrong-label, over-long-edge, and duplicate-pixel
counters are unchanged. Dense, high-corner-count frames are where the two
criteria disagree most: some lose a small fraction of labelled corners
relative to the fit-RMS rule. If you pinned a minimum-corner expectation
against a very dense board, re-measure it.

## 5. `chess_corners::low_level` moved to `chess-corners-core`

The `low_level` and `unstable` modules are removed from the `chess-corners`
facade. The contract they exposed now lives at the root of the
`chess-corners-core` crate, which you must depend on directly.

```toml
# Cargo.toml
chess-corners = "1.0"
chess-corners-core = "1.0"   # only if you drive the response/detect stages by hand
```

```rust
// before
use chess_corners::low_level::{ChessParams, RefinerKind, ImageView, Roi};

// after
use chess_corners_core::{ChessParams, RefinerKind, ImageView, Roi};
```

`chess_response_u8_patch`, `detect_corners_from_response_with_refiner`, and
`Refiner` move the same way.

**`PyramidParams` is not re-exported by 1.0** — it moved to
`box-image-pyramid`. Construct
`MultiscaleConfig::Pyramid { levels, min_size, refinement_radius }` directly
instead of routing through a `PyramidParams` intermediate.

Refiner configs are `#[non_exhaustive]` upstream now, so struct literals no
longer compile; use `default()` plus field assignment.

## 6. `nalgebra` 0.34 → 0.35

`nalgebra` types appear in the public API of `projective-grid` and
`calib-targets-core` (`Point2<f32>`, `Matrix3<f32>`,
`LabeledCorner.position`, …), so consumers must move to the same major
version to interoperate. No workspace source change was required and
detection output is byte-identical.

The bump also drops the unmaintained `paste` crate from the `nalgebra` →
`simba` path (see the CHANGELOG *Security* section).

---

## 7. `GridCoords` is replaced by `Coord { u, v }`

The workspace-local `GridCoords { i, j }` type is deleted with no deprecated
alias; `projective_grid::Coord { u, v }` is the single canonical
grid-coordinate type, re-exported from `calib-targets-core` and the facade.

**The axis convention is preserved exactly**: the old `i` (grid-right, first
axis) is `Coord::u`, and the old `j` (grid-down, second axis) is `Coord::v`.

Affected output fields: `LabeledCorner.grid`, `ChessboardCorner.grid`,
`CharucoCorner.grid`, `MarkerBoardCorner.grid`, `PuzzleBoardCorner.grid`,
`MarkerDetection.gc`, `ResolvedTargetPoint.grid`.

### Report JSON

```jsonc
// before
{ "grid": { "i": 3, "j": 5 } }

// after
{ "grid": { "u": 3, "v": 5 } }
```

The marker-board *cell* index (`MarkerCircleSpec.cell`, Rust `CellCoords`) is
**unaffected** and keeps its `{ "i", "j" }` shape.

**The C ABI is unchanged here.** `ct_grid_coords_t` keeps its historical
`{ i, j }` C field names and struct layout; the Rust→C conversion maps
`Coord::u → i` and `Coord::v → j`.

## 8. The seed-and-grow grid builder is retired

`Topological` is the sole grid builder. Both seed-and-grow engines — the
chessboard pipeline's own and `projective-grid`'s
`SquareAlgorithm::SeedAndGrow` — are deleted, and ChArUco, PuzzleBoard, and
marker boards all run the topological builder now.

- `GraphBuildAlgorithm` and `SquareAlgorithm` collapse to single-variant
  `#[non_exhaustive]` enums (only `Topological`), retained as reserved config
  seams.
- **The wire string `"seed_and_grow"` no longer deserializes.** Remove it
  from stored configs.
- The chessboard `AdvancedTuning` block drops its seed-and-grow-only stage
  knobs: `seed_*`, `rescue_*`, `refit_*`, `boundary_extension_*`,
  `partial_slot_flip_*`, and the dead BFS-validate tolerances. The removal is
  propagated through the FFI / Python / WASM / Studio surfaces.
- The chessboard rich `DebugFrame` diagnostics and the experimental
  `OrientationSource::NeighbourEdges` path are removed with the engine.

A `min_corner_strength` floor now pre-filters the marker-bit corners that the
old ChArUco engine pin had guarded against.

## 9. Smaller surface removals

- **`calib_targets_chessboard::Detector::new` is now fallible**
  (`-> Result<Self, ChessboardParamsError>`), validating the configuration up
  front. The previous infallible `new` + `try_new` pair is gone — rename your
  `try_new` calls to `new`. `MarkerBoardDetector::new` is likewise fallible,
  and `PuzzleBoardSpecError` gains a `Chessboard` variant so
  `PuzzleBoardDetector::new` surfaces an invalid embedded chessboard config.

- **The legacy ChArUco vote matcher is retired.** The board-level matcher was
  already the default, so detection behaviour is unchanged.
  `CharucoParams::use_board_level_matcher` and `CharucoParams::max_hamming`
  are removed (both keys are now ignored on deserialization).
  `MatcherDiagKind` and `ComponentDiagnostics.matcher` are removed, so the
  `matcher` key is dropped from the ChArUco diagnostics JSON.

- **ChArUco and PuzzleBoard diagnostics are behind an opt-in `diagnostics`
  cargo feature** (default off), matching `calib-targets-chessboard`. The
  `diagnostics` module, its type re-exports, and `detect_with_diagnostics`
  reach the public surface only with the feature enabled; the facade
  `calib-targets/diagnostics` feature forwards to all three detector crates.

  ```toml
  # Cargo.toml — turn the surface back on
  calib-targets = { version = "0.11", features = ["diagnostics"] }
  ```

- **`DetectorParams.min_labeled_corners` / `max_components` are defaulted on
  deserialization** (`8` / `3`), so partial and legacy configs that omit them
  deserialize again. Values and serialization are unchanged. *(Not a break —
  listed here because it changes what your stored configs do.)*

## C ABI: `calib-targets-ffi` → 3.0.0

Three struct-layout-breaking changes land in this cycle. Recompile C/C++
consumers against the regenerated `calib_targets_ffi.h`; `ct_version_string()`
and the CMake config-version now report `3.0.0`.

1. **`ct_chess_params_t`** collapses `threshold_rel` (`float`) +
   `threshold_abs` (`ct_optional_f32_t`) into one absolute `threshold`
   (`float`), and drops `descriptor_use_radius10`.
2. **`ct_chessboard_advanced_t`** drops `max_fit_rms_ratio` along with the
   rest of the pre-filter section.
3. **`ct_charuco_detector_params_t`** drops `max_hamming` (it only fed the
   retired ChArUco vote matcher).

The **`ct_optional_bool_t` type is removed entirely** — nothing declares an
optional boolean any more. Delete any local `none_bool()`-style helper.

```c
/* before */
config.chess.params.descriptor_use_radius10 = none_bool();
config.chess.params.threshold_rel = 0.2f;
config.chess.params.threshold_abs = none_f32();

/* after */
config.chess.params.threshold = 15.0f;
```

`ct_grid_coords_t` is **unchanged** — see [theme 7](#7-gridcoords-is-replaced-by-coord--u-v-).

## Python

- **`Threshold` and `DescriptorRing` are deleted** from
  `calib_targets.config` and from `__all__`. `ChessConfig.threshold` is a
  plain `float`, defaulting to `15.0`.
- **`DetectionParams` is new.** `nms_radius` and `min_cluster_size` move off
  `ChessStrategyConfig` onto `ChessConfig.detection`.
- Both the old threshold dict shape and the old key locations are **rejected
  with an explicit error** rather than silently defaulting, so a stale config
  fails loudly.

```python
# before
cfg = ct.ChessConfig(
    threshold=ct.Threshold.absolute(15.0),
    strategy=ct.DetectionStrategy.chess(
        ct.ChessStrategyConfig(nms_radius=2),
    ),
)

# after
cfg = ct.ChessConfig(
    threshold=15.0,
    detection=ct.DetectionParams(nms_radius=2),
)
```

Attribute paths change accordingly:

```python
# before
params.chessboard.chess.strategy.chess_config.nms_radius

# after
params.chessboard.chess.detection.nms_radius
```

`ChessboardParams.max_fit_rms_ratio` (one of the advanced knobs that
`to_dict` nests under `"advanced"`) is removed. Grid coordinates are
`Coord(u, v)`; the marker `CellCoords(i, j)` is retained.

## WASM / TypeScript

The published `ChessConfig` type now mirrors the real serde tree (the
declaration had drifted from the wire format in earlier releases):

```ts
interface ChessConfig {
  strategy: DetectionStrategy;      // { chess: { ring, refiner } } | { radon: … }
  threshold: number;                // was: { absolute: number } | { relative: number }
  detection: DetectionParams;       // { nms_radius, min_cluster_size } — new location
  multiscale: MultiscaleConfig;
  upscale: UpscaleConfig;
  orientation_method: OrientationMethod | null;
  merge_radius: number;
}
```

`Corner` drops `contrast` and `fit_rms`. `descriptorRing` / `ThresholdMode`
are removed. Grid-coordinate fields are `Coord { u, v }`.

> **Build order.** Run `scripts/build-wasm.sh` **before** `bun install` in
> `demo/` — `pkg/` is gitignored and copied at install time, so a stale `pkg`
> produces phantom TypeScript errors about missing exports.

## Verifying your migration

```bash
cargo build --workspace
cargo test --workspace
```

For the bindings:

```bash
cargo run -p calib-targets-ffi --features generate-header \
  --bin generate-ffi-header -- --check
uv run pytest crates/calib-targets-py/python_tests/
scripts/build-wasm.sh
```

If you keep a golden corner set, expect it to compare equal except where
theme 4 applies — and if a `(i, j)` label ever changes value (as opposed to a
corner appearing or disappearing), that is a bug worth reporting, not an
expected migration effect.
