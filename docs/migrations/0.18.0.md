# Migrating to 0.18.0

**Breaking for Rust callers of the facade.** The `detect_*` and `blur`
functions borrow a `GrayImageView` instead of taking an `image::GrayImage`,
and the five `detect_*_best` sweeps share one set of rules. The Python and
WASM detection calls keep their signatures; only the sweep error behaviour
changes there.

Labels change in two ways (see the [CHANGELOG](../../CHANGELOG.md)): dense,
strongly distorted chessboards gain corners, and a ChArUco fragment is merged
only when its geometry agrees with the rest of the board.

## The facade takes `&GrayImageView`

Every `calib_targets::detect::*` and `calib_targets::blur::*` function that
took `&image::GrayImage` now takes `&GrayImageView<'_>`. Borrow your image
with `detect::gray_view` — no copy is made:

```rust,ignore
// Before
let det = calib_targets::detect::detect_chessboard(&img, &chess_cfg, &params);

// After
use calib_targets::detect::{detect_chessboard, gray_view};
let det = detect_chessboard(&gray_view(&img), &chess_cfg, &params);
```

Raw buffers: `detect::gray_image_from_slice(w, h, &px)` is replaced by
`detect::gray_view_from_slice(w, h, &px)`, which borrows `px`. A zero width or
height is now rejected as `DetectError::InvalidGrayDimensions` (it used to run
and miss); the `detect_*_from_gray_u8` helpers inherit this.

`detect` and `blur` no longer need the `image` feature. With
`default-features = false` you build `GrayImageView` yourself; the `image`
feature only adds `gray_view`, `preprocess` and the `image` re-export, and it
no longer pulls in `chess-corners`.

## `detect_*_best` sweeps

All five sweeps (`detect_chessboard_best`, `detect_charuco_best`,
`detect_puzzleboard_best`, `detect_puzzlepole_best`,
`detect_marker_board_best`) follow one contract:

| Situation | 0.17 | 0.18 |
|---|---|---|
| Empty config list | a miss (`NoDetection`, `CharucoDetect(NoMarkers)`, …) | `DetectError::EmptySweep { op }` (misuse, `is_not_found() == false`) |
| An invalid config in the list | skipped | the sweep stops and returns that error |
| Two configs tie on the score | chessboard / marker board: last wins; others: first wins | first wins everywhere |

Order sweep presets by preference: the earlier config wins a tie. Match on
`DetectError::EmptySweep` if you build config lists dynamically (the enum is
`#[non_exhaustive]`, so existing `_` arms keep compiling).

**Python / WASM:** `detect_*_best(image, [])`, or a list containing an invalid
config, now raises `ValueError` / throws instead of returning `None` / `null`.

## Smaller changes

- `MarkerBoardDetector::new` returns `MarkerBoardParamsError`; the facade
  reports it as `DetectError::MarkerBoardParams` (was
  `DetectError::ChessboardParams`).
- ChArUco `MarkerDetection::score` is `exp(mean bit log-likelihood)` in
  `(0, 1]` (it was a sigmoid that never exceeded 0.5). Re-check any threshold
  you apply to it.
- `PuzzlePoleDetector::new` refuses `min_circumference_span < 5` or
  `min_axial_span < 8` (`PuzzlePoleDetectError::WindowBelowFloor`): smaller
  windows admit placements that provably alias.
- `calib_targets_core::axis_estimate_to_next(axis)` → `LocalAxis::from(axis)`.
- Binaries behind features: `cargo run -p calib-targets-puzzleboard --features
  tools --bin …` for the code-map tools, `--features package-archive` for the
  FFI `package-release-archive`.
- `projective-grid` 0.15: `expert::lattice::GRID_TRANSFORMS_D4` is removed in
  favour of `D4_TRANSFORMS`, which now has that order. Code that indexes
  `D4_TRANSFORMS[k]` directly gets a different transform for `k = 1, 3`.
  `calib_targets_core::GRID_TRANSFORMS_D4` keeps its values and order.
